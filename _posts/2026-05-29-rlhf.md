# RLHF: 인간의 선호를 보상으로 학습시키는 방법

이 글은 RLHF(Reinforcement Learning from Human Feedback)의 기본 흐름을 정리한 글이다.

핵심은 간단하다. 사람이 직접 보상 함수를 수식으로 정의하는 대신, 사람이 더 좋다고 고른 답변 데이터를 이용해 reward model을 학습하고, 그 reward model을 기준으로 LLM을 강화학습시키는 방법이다.

```text
Human Preference
   -> Reward Model
   -> Policy Optimization
   -> Aligned Language Model
```

RLHF는 ChatGPT 같은 instruction-following 모델을 이해할 때 중요한 개념이다. 사전학습 언어 모델이 "다음 token을 잘 맞히는 모델"이라면, RLHF는 그 모델을 "사람이 더 선호하는 방식으로 답하는 모델"에 가깝게 조정한다.

## 1. 왜 RLHF가 필요한가

대규모 언어 모델은 next-token prediction만으로도 뛰어난 언어 능력을 얻는다. 하지만 실제 대화형 서비스에 쓰려면 다음 문제가 남는다.

- 사용자의 의도를 제대로 따르지 않는 답변
- 맞는 말처럼 보이지만 실제로는 틀린 답변
- 너무 길거나 짧거나 불친절한 답변
- 유해하거나 편향된 응답
- "좋은 답변"을 명확한 loss function으로 쓰기 어려운 문제

사람은 두 답변을 보고 어느 쪽이 더 좋은지 비교할 수 있다. 하지만 "좋음"을 하나의 수식으로 직접 정의하기는 어렵다.

RLHF는 이 간극을 줄인다. 사람이 제공한 선호 비교 데이터를 학습해, 모델이 최적화할 수 있는 reward signal로 바꾸는 것이다.

## 2. RLHF의 전체 흐름

RLHF는 보통 세 단계로 설명할 수 있다.

| 단계 | 목표 | 데이터 |
|---|---|---|
| Pretraining | 언어 생성 능력 학습 | 대규모 텍스트 |
| Supervised Fine-Tuning | instruction을 따르는 기본 패턴 학습 | 사람이 작성한 instruction-response |
| Reward Model + RL | 인간 선호에 맞게 policy 최적화 | 응답 pair에 대한 preference |

전체 흐름은 다음처럼 볼 수 있다.

```text
1. Pretrained LM
2. SFT model
3. Reward model training
4. PPO 등으로 policy optimization
```

## 3. Pretraining

먼저 모델은 대규모 텍스트로 next-token prediction을 학습한다.

```text
prefix -> next token
```

이 단계의 목표는 문법, 지식, 표현, 일반적인 언어 패턴을 배우는 것이다. 하지만 pretraining만으로는 사용자의 지시를 잘 따르는 모델이 되기 어렵다.

예를 들어 pretraining 모델은 질문에 답하기보다 웹 문서의 다음 문장을 이어 쓰는 방식으로 반응할 수 있다. 그래서 instruction-following을 위한 추가 단계가 필요하다.

## 4. Supervised Fine-Tuning

SFT는 사람이 작성한 좋은 instruction-response 예시로 모델을 fine-tuning하는 단계다.

예시는 다음과 같다.

```json
{
  "instruction": "문장을 더 정중하게 바꿔줘",
  "input": "빨리 보내줘",
  "output": "가능하시다면 빠르게 보내주시면 감사하겠습니다."
}
```

이 단계에서 모델은 사용자의 요청을 읽고 적절한 형식으로 답하는 기본 패턴을 배운다.

하지만 SFT만으로는 부족할 수 있다. 좋은 답변은 하나로 고정되지 않고, 길이, 톤, 안전성, 구체성, 사실성 같은 여러 기준을 함께 만족해야 하기 때문이다.

## 5. Reward Model Training

Reward model은 인간의 선호를 점수로 근사하는 모델이다.

보통 데이터는 pairwise preference 형태로 만든다.

```text
Prompt: "RLHF를 설명해줘"

Answer A: 간단하고 정확한 설명
Answer B: 장황하고 부정확한 설명

Human preference: A
```

reward model은 다음 관계를 만족하도록 학습된다.

$$
R(prompt, answer_A) > R(prompt, answer_B)
$$

즉 절대적인 정답 점수를 직접 주는 것이 아니라, 두 답변 중 어느 쪽이 더 나은지 비교하는 데이터를 학습한다.

이 방식은 현실적이다. 사람에게 "이 답변은 87점"이라고 점수를 매기게 하는 것보다, "A와 B 중 어느 쪽이 더 좋은가"를 묻는 편이 훨씬 쉽기 때문이다.

## 6. Policy Optimization

reward model이 만들어지면, 언어 모델을 reward가 높아지는 방향으로 업데이트한다.

LLM을 강화학습 관점으로 보면 다음과 같다.

| 강화학습 개념 | LLM에서의 의미 |
|---|---|
| State | 지금까지 생성된 token sequence |
| Action | 다음 token 선택 |
| Policy | 다음 token 확률 분포 |
| Reward | reward model이 준 답변 점수 |

실제로는 PPO 같은 알고리즘이 자주 사용된다. PPO는 모델이 reward를 높이되, 기존 SFT model에서 너무 멀어지지 않도록 제한한다.

왜 제한이 필요할까?

reward model은 인간 선호를 완벽하게 표현하지 못한다. 모델이 reward model의 빈틈을 찾아 점수만 높이는 방향으로 망가질 수 있다. 이를 reward hacking이라고 한다.

## 7. Reward Hacking과 KL Penalty

Reward hacking은 모델이 실제로 좋은 답변을 만드는 것이 아니라, reward model이 좋아할 만한 표면적 패턴만 악용하는 현상이다.

예를 들어 reward model이 특정 표현이나 길이를 과하게 선호하면, policy model은 답변의 실제 유용성과 무관하게 그런 패턴을 반복할 수 있다.

이를 막기 위해 RLHF에서는 보통 KL penalty를 둔다.

```text
reward는 높이고 싶다.
하지만 SFT model의 분포에서 너무 멀어지면 안 된다.
```

이 제약은 모델이 인간 선호를 따라가면서도 기존 언어 능력과 안정성을 잃지 않게 도와준다.

## 8. 한계점

RLHF는 강력하지만 한계도 분명하다.

### 인간 선호 데이터의 품질에 의존한다

labeler가 어떤 기준으로 답변을 고르는지에 따라 reward model이 달라진다. 선호 데이터가 편향되어 있으면 모델도 그 편향을 학습할 수 있다.

### Reward model은 완벽한 보상 함수가 아니다

reward model은 인간 평가를 근사한 모델일 뿐이다. 따라서 policy가 reward model을 과하게 최적화하면 실제 인간이 보기에는 좋지 않은 답변이 나올 수 있다.

### 비용이 크다

좋은 preference dataset을 만들려면 많은 human annotation이 필요하다. 또한 reward model 학습과 policy optimization도 추가 비용을 만든다.

### 정답 기준이 모호한 task에서 어렵다

창의적 글쓰기, 윤리적 판단, 복잡한 조언처럼 답변 품질 기준이 상황에 따라 달라지는 task에서는 선호 신호 자체가 불안정할 수 있다.

## 9. 이 방법의 핵심 의의

RLHF의 의의는 LLM 학습 목표를 next-token prediction에서 인간의 사용 기준 쪽으로 옮겼다는 데 있다.

pretraining은 "인터넷 텍스트를 잘 이어 쓰는 능력"을 만든다. SFT는 "instruction에 답하는 형식"을 만든다. RLHF는 그 위에 "사람이 더 선호하는 답변"이라는 기준을 얹는다.

이 흐름은 이후 alignment 연구의 중심축이 되었다.

- helpfulness: 사용자의 문제를 실제로 해결하는가
- harmlessness: 안전하고 유해하지 않은가
- honesty: 모르는 것을 아는 척하지 않는가
- instruction following: 요청한 형식과 의도를 따르는가

## 내가 이해한 핵심

RLHF는 다음 한 줄로 요약할 수 있다.

```text
사람의 선호 비교를 reward model로 학습하고,
그 reward를 기준으로 LLM policy를 조정한다.
```

이 방법은 LLM을 실제 사용자와 맞닿은 제품으로 만드는 데 중요한 역할을 했다. 다만 reward model이 인간의 판단을 완벽히 대체하는 것은 아니므로, 데이터 품질, reward hacking, 평가 기준의 모호성을 항상 함께 고려해야 한다.

## 한 줄 요약

RLHF는 인간이 선호하는 답변 비교 데이터를 reward model로 바꾸고, 그 보상을 기준으로 언어 모델을 조정해 instruction-following과 alignment를 개선하는 방법이다.
